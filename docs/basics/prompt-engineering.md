# Prompt Engineering 入门

> 当前状态：已完成基础版  
> 适合读者：希望提升 AI 输出稳定性的人

## 这篇文章解决什么问题

很多人以为提示词工程就是“会不会写几句咒语”。更准确的理解是：它是一种任务表达能力。你越能把目标、上下文、约束和验收标准说清楚，模型输出越稳定。

## Prompt 的本质

Prompt 不是一句问题，而是一份任务说明。它告诉模型：

- 你是谁，要做什么
- 可以使用什么上下文
- 结果要长什么样
- 哪些边界不能碰

## 一个稳定 Prompt 的常见结构

### 1. 任务目标

先明确你要模型完成什么动作，比如总结、分类、改写、抽取、比较、生成方案，不要把多个目标混成一句。

### 2. 上下文材料

把模型完成任务所需的背景、样例、输入数据、受众说明放进去。上下文不足时，模型只能靠猜。

### 3. 输出约束

明确格式、字数、结构、语言风格、禁止项、是否要表格、是否要 JSON。输出越可验证，越容易稳定。

### 4. 验收标准

告诉模型什么叫“好结果”。例如“不得编造不存在的政策”“必须保留术语原文”“先给摘要再给明细”。

## 常见提示方式

| 方式          | 适用场景         | 说明                                     |
| ------------- | ---------------- | ---------------------------------------- |
| 直接指令      | 简单任务         | 适合摘要、改写、翻译、分类               |
| Few-shot 示例 | 风格或格式要求强 | 通过示例降低理解偏差                     |
| 角色设定      | 需要明确视角     | 让模型按产品经理、编辑、分析师等角色回答 |
| 分步要求      | 复杂任务         | 先拆解再生成，降低一步到位失败率         |

## 一个简单模板

```text
你现在要完成的任务是：
<目标>

可用背景信息：
<上下文>

输出要求：
1. <结构要求>
2. <格式要求>
3. <禁止项>

验收标准：
<什么样的结果算合格>
```

## 常见误区

### 一次塞进太多目标

“帮我分析、总结、改写、翻译并提出建议”这类提示，经常导致输出既不聚焦也不稳定。复杂任务应该拆成多个步骤。

### 只写目标，不给上下文

模型并不知道你的业务背景、目标受众和已有约束。背景缺失时，输出通常会空泛或跑偏。

### 只关注措辞，不关注验收

提示词工程的核心不是“更像人说话”，而是“更容易得到可验证结果”。

## 落地建议

1. 把高频任务沉淀成固定模板。
2. 为每类任务准备 2 到 3 个对照示例。
3. 对关键输出增加结构化格式要求，方便后续校验或接入系统。
